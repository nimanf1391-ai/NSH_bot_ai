# راهنمای نسخهٔ هماهنگ‌شدهٔ NSH.bot

این بسته بر پایهٔ فایل ZIP ارسالی کاربر ساخته شده است.

## محتویات
- `public/index.html`: همان فایل سایت ارسالی؛ ظاهر و تغییرات موجود حفظ شده است.
- `supabase/functions/login-code/index.ts`: نسخهٔ هماهنگ‌شده با هدر `x-session-token`، عملیات `session_me`، همگام‌سازی و محدودیت درخواست‌ها.
- `schema-supabase.sql`: فایل schema اصلی موجود در بستهٔ ارسالی؛ تغییر داده نشده است.

## نکات مهم
1. فایل HTML داخل این بسته از قبل به آدرس تابع `login-code` وصل است و هدر `x-session-token` را می‌فرستد.
2. کد تابع از RPC با نام `nsh_rate_limit` استفاده می‌کند؛ SQL مربوط به این تابع باید قبلاً در SQL Editor اجرا شده باشد.
3. در Supabase باید `SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` و `OWNER_PHONE` تنظیم باشند. `ADMIN_SECRET` فقط برای bootstrap صدور اولین کد مالک در تست امن داشبورد است و هرگز نباید داخل HTML قرار بگیرد.
4. تابع باید با Verify JWT خاموش منتشر شود، چون نشست اختصاصی با `x-session-token` بررسی می‌شود.
5. این بسته را ابتدا در یک نسخهٔ پشتیبان نگه دارید. قبل از جایگزینی فایل‌های GitHub Pages، تست ورود مالک، صدور کد، `session_me` و `sync_get`/`sync_save` انجام شود.
6. تست موفق `sync_save` با دادهٔ آزمایشی به‌تنهایی به معنی تست کامل همگام‌سازی همهٔ داده‌های سایت نیست.
